# 中转站返回 200，body 是登录页

## 现象

**不报错的地方在这儿**：HTTP 状态码 200，看起来一切正常。但前端收到的是：

```
Unexpected token '<', "<!DOCTYPE "... is not valid JSON
```

或者后端 Jackson 报：

```
com.fasterxml.jackson.core.JsonParseException: Unexpected character ('<' (code 60))
```

关键在于：**状态码是 200**，所以重试逻辑不会触发，监控也不会报警。

## 为什么

中转站（第三方 API 代理）在几种情况下会把请求导向 HTML 页面，而不是 JSON 接口：

| 情况 | 返回的内容 |
| --- | --- |
| key 不在该分组下 | 站点的登录/充值页 |
| `base_url` 少了 `/v1` | 站点首页（200） |
| 站点在维护 | 公告页 |
| 域名被 CDN 接管 | 云厂商的错误页 |

浏览器访问能打开页面，于是你以为「服务是通的」—— 但它通的是**网页**，不是 API。

## 怎么改

### 一、先确认 endpoint 形状

```
错：https://api.example.com/chat/completions
对：https://api.example.com/v1/chat/completions
```

很多中转站同时暴露站点首页和 `/v1` 接口，少一段就被路由到首页。

### 二、用 curl 看真实响应

```bash
curl -i https://api.example.com/v1/chat/completions \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o-mini","messages":[{"role":"user","content":"hi"}]}'
```

看两行就够：

```
HTTP/2 200
content-type: text/html      ← 这就是问题
```

### 三、代码里拦一道

```java
if (!resp.headers().firstValue("content-type").orElse("").contains("json")) {
    throw new UpstreamException("上游返回了非 JSON：" + resp.statusCode() + " " +
        resp.body().substring(0, Math.min(160, resp.body().length())));
}
```

**没有这道检查，200 会一路穿到业务层**，最后在某个奇怪的地方炸。

## 怎么预防

- 应用启动时做一次 `/models` 探活并**校验 Content-Type**，而不是只校验状态码
- 换中转站时先跑一遍 curl 冒烟，别直接改配置上线
- 监控上把「content-type 不是 JSON 的响应」单独计数 —— 这类失败不会被状态码统计捕获

## 环境

| 组件 | 版本 |
| --- | --- |
| 调用方 | 任意 HTTP 客户端 |
| 触发条件 | base_url 错误、key 分组不匹配、中转站维护 |
| 相关异常 | `JsonParseException`、`Unexpected token '<'` |
