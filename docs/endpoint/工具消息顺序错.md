# 工具调用报 400：tool 消息必须紧跟在 tool_calls 后面

## 报错

```
400 Invalid parameter: messages with role 'tool' must be a response to a preceding message
with 'tool_calls'
```

另一种同源形态：

```
400 An assistant message with 'tool_calls' must be followed by tool messages
responding to each tool_call_id
```

## 为什么

工具调用的消息序列有**严格的结构要求**，不是随便往里塞：

```
user       我要查订单 A123 的状态
   ↓
assistant  tool_calls: [{id: "call_1", function: "queryOrder", args: {...}}]
   ↓
tool       tool_call_id: "call_1"   content: "已发货"
   ↓
assistant  根据查询结果，你的订单已发货
```

两条硬规则：

1. **`tool` 消息必须紧跟在带 `tool_calls` 的 `assistant` 消息之后**，中间不能插别的东西
2. **每个 `tool_call_id` 都必须有对应的 `tool` 消息**；并行调用 N 个工具，就要回 N 条

最常见的破坏方式是：**把历史消息截断时按条数砍**，一刀切掉了 `tool_calls`，留下了 `tool`。

```java
// 错：只保留最近 10 条
List<Message> recent = history.subList(history.size() - 10, history.size());
```

## 怎么改

### 一、截断按「对话轮」而不是按「条」

```java
List<Message> trimmed = new ArrayList<>();
int tools = 0, assistant = 0;
for (Message m : reversed(history)) {
    trimmed.add(0, m);
    if ("tool".equals(m.role())) tools++;
    if ("assistant".equals(m.role()) && m.toolCalls() != null) assistant++;
    if (trimmed.size() >= 10 && tools == assistant) break;   // 只在不拆组时断开
}
```

### 二、每条 `tool` 都要有 id，且 id 不能重复

```java
Message.toolMessage(toolCall.id(), result)   // ✅
Message.toolMessage("call_1", result)        // ❌ 硬编码，并行时全撞一起
```

LangChain4j 里对应的是 `ToolExecutionResultMessage`，同样按 id 配对。

### 三、并行调用一次回全

模型一次返回多个 `tool_calls` 时，**必须一次性把结果补齐**，不能先回一个、等下一轮再回另一个：

```java
for (ToolCall call : response.toolCalls()) {
    messages.add(Message.toolMessage(call.id(), execute(call)));
}
```

## 怎么预防

- 消息组装只走一个构造器，业务层不允许直接 `messages.add(...)`
- 加一个断言：发送前校验「每个 tool_call_id 都有对应 tool 消息」，不满足就本地报错，别浪费一次请求
- 上下文截断是重灾区，单独写单测覆盖「截断点落在工具调用中间」的情况
