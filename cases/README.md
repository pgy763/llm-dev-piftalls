# 能跑的复现

手册告诉你「会这样」，这一组测试告诉你怎么亲眼看到它这样。

十条最高频的坑，每条一个测试类，**不联网、不要 API key、不连数据库**，`mvn test` 十秒跑完。

## 怎么跑

```bash
cd cases
mvn -B test
```

需要 **JDK 17+** 和 Maven。第一次会下载 JUnit / Jackson / HikariCP（十来兆），之后离线可跑。

> Windows 控制台里中文是乱码的话，先 `chcp 65001`，或者直接看 `target/surefire-reports/` 下的 html。

## 每个测试类里有两个方法

| 方法 | 断言的是 | 通过了说明 |
| --- | --- | --- |
| `复现()` | **错误行为真的会发生** | 这个坑是真的，不是你多疑 |
| `对照()` | **改法真的有效** | 你知道怎么修，而且修完确实不犯了 |

所以 `mvn test` 全绿不代表没坑 —— 它代表**坑被固定住了**，像给 bug 拍了个标本。

想看红的？两个办法：

- 把 `对照()` 里那几行改法删掉，它就会失败 —— 失败信息就是「不这么写会怎样」
- 把 `复现()` 的断言改成「应该正常」，它会红 —— 红的那行就是你要改的代码

## 十条

| # | 坑 | 对应手册 | 复现的是 |
| --- | --- | --- | --- |
| 01 | SSE 中文乱码 | [SSE响应中文乱码](../docs/java/SSE响应中文乱码.md) | UTF-8 字节被按 GBK 解，中文变错字 |

| 08 | 多用户共用 ChatMemory | [多用户共用一份ChatMemory](../docs/java/多用户共用一份ChatMemory.md) | B 的上下文里出现 A 的名字 |

## 为什么不用真模型

这十条的触发点全在**协议层和状态管理**上 —— 编码、缓冲、连接池、幂等、断连。换成哪个厂商的模型都会发生，用真模型只会让复现变成「要 key、要花钱、结果还不确定」。

所以 03 / 04 用一个假网关，06 用本机 `HttpServer` 起一个真会返回 502 HTML 的接口，09 用一个会抛 `Connection reset by peer` 的假响应流。它们的行为和真实环境一致，只是不产生费用。

## 这不是生产代码

- 是最小复现，故意省掉了重试退避、熔断、日志脱敏这些；看的是「坑长什么样」，不是「照抄就能上线」
- 02 / 03 / 05 有时间断言（300ms 级），留了较宽余量；机器极慢时可能抖动，重跑一次即可
- 复现的是**通用机制**，不是某个版本的行为；手册条目里标注的版本差异仍然成立
